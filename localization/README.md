# Работа с русской локализацией

`src/Data/Locale` содержит готовые таблицы, применяемые при отображении и поиске. Исходные ID, расчёты и сериализация используют формат исходной PoB. Обработка вставки русского предмета выполняется отдельно в `src/Modules/ItemClipboardLocale.lua`.

## Повторить выпуск

Полный клон этой ветки включает исходники, готовые каталоги и Windows runtime. Доступ к игровым файлам и аккаунту автора для сборки не требуется.

```powershell
python scripts/build_ru_release.py
python scripts/test_ru.py --directory dist/PoB2-RU-0.23.1-ru.1-beta.3
```

Сборка читает `localization/portable-files.json` — явный список путей и SHA-256. Изменённый исходник требует проверки и явного обновления манифеста:

```powershell
python scripts/build_ru_release.py --refresh-manifest --output dist-reviewed
```

Скрипт создаёт новый каталог, ZIP и `SHA256SUMS.txt`. Он проверяет каждый файл архива. Уже существующая папка выпуска не перезаписывается.

## Изменить интерфейс

Каталоги `localization/catalogs/*.tsv` содержат английский ключ и русский текст, разделённые табуляцией. После изменения:

```powershell
python scripts/compile_ru_catalogs.py
```

Устройство локализации и раскладка элементов находятся в `src/Modules/UILocale.lua`, `CharacterImportLocale.lua`, `BuildWarningLocale.lua` и в классах интерфейса. Новые подписи проверяются в русском и английском режимах, включая узкие окна и реальные асинхронные состояния.

## Обновить игровые строки

В `localization/development` сохранены исходные скрипты генерации и патчи, использованные при разработке. Они документируют первоначальный процесс с отдельными папками `work/PoB2-baseline`, `work/PoE2-game-extract`, `work/upstream-downloads` и `outputs/PoB2-RU`. Это инструменты обновления данных, а не установщик и не обязательный этап повторной упаковки готового выпуска.

Исходные дампы клиента, личные сохранения и ответы API не публикуются. Перед новой версией нужно подготовить данные нужного клиента, восстановить входные выгрузки английских объектов PoB и схемы DAT по зафиксированным источникам, затем повторить сопоставление по ID и проверки. Вспомогательный модуль `gamedata.py` первоначально получен из проекта [JavelinSx/poe2lab](https://github.com/JavelinSx/poe2lab); он не включён в этот набор скриптов. Сформированные таблицы текущей версии включены полностью.

Метаданные источников находятся в `localization/release.json`, отчёты о покрытии — в `localization/coverage`. Записи без надёжного соответствия сохраняют исходное написание и перечисляются в отчётах.

## Проверки

`scripts/test_ru.py` запускает проверки на искусственном билде с «Искрой», без настроек и токенов автора. Проверяются загрузка, расчёты, код билда, отображение, импорт персонажа, параметры торговли и список результатов. Сетевые запросы в этих тестах блокируются.

Проверки с Windows DLL выполняются на Windows. Сам скрипт упаковки использует стандартную библиотеку Python.

Живой импорт и торговый поиск отдельно проверены владельцем. Числовое равенство с исходной PoB проверялось на шести локальных сценариях; частные билды из этих проверок в репозиторий не включены.
