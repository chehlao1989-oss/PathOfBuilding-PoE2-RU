Публичный адрес: https://chehlao1989-oss.github.io/PathOfBuilding-PoE2-RU/

Дизайн «Атлас» выбран владельцем 18 ноября 2026 года. Сайт — статические HTML, CSS и JavaScript без сборщика и внешних библиотек. GitHub Pages публикует каталог `/docs` ветки `ru-release`. `.nojekyll` отключает обработку Jekyll. Основная программа и архивы выпуска не зависят от сайта.

## Главная и FAQ — редакция от 19 ноября 2026 года

По поручению владельца переработаны композиция и тексты главной. Первый экран теперь содержит H1 «PoB 2 на русском», пояснение назначения программы, скачивание и проверенные версии. Возможности представлены по разделам программы, установка — последовательными действиями.

FAQ содержит девять вопросов. Первый — «Есть ли поба на русском для PoE 2?» — раскрыт сразу. Остальные объясняют скачивание, импорт кодов и pobb.in, своего персонажа, торговлю, версии, пропуски перевода, сохранение билдов и обновления. Все ответы находятся в исходном HTML, раскрытие работает без JavaScript. Ключевые формулировки используются в видимом содержимом; скрытые SEO-тексты и обещания мест в поиске не добавлялись.

Сохранены исходный canonical, метатег подтверждения владельца, ссылки на beta 2, JSON-LD SoftwareApplication и прежние изображения. `lastmod` в Sitemap отражает это изменение. При следующем выпуске обновлять версии также в ответе FAQ о поддерживаемых версиях, а не только возле кнопок и в JSON-LD.

Проверки 19 ноября: отдельный Chrome без доступа к пользовательскому профилю, ширины 320, 360, 390, 768, 1024, 1440 и 1920. Проверены отсутствие горизонтального переполнения, загрузка изображений, три переключателя галереи, увеличение и закрытие Escape, FAQ мышью и клавиатурой, ссылка перехода к содержимому и работа без JavaScript. Локальная браузерная проверка выполнена через `file://`: localhost недоступен между средами; это не HTTP-проверка опубликованной версии и не измерение Core Web Vitals. Свидетельства у владельца: `outputs/website/redesign-checks/verification.json` и изображения в той же папке.

## При новом выпуске

Сохранять метатег `google-site-verification` в `<head>` главной страницы: он добавлен по коду, предоставленному владельцем для Google Search Console. Публикация метатега — отдельный шаг; подтверждение ресурса и отправка Sitemap выполняются в аккаунте владельца.

1. Сверить поддерживаемые версии PoB и игры с `localization/release.json`, README и отчётом QA. Не обещать совместимость с будущей игрой до отдельной проверки.
2. В `index.html` обновить обе ссылки скачивания ZIP, ссылки на страницу выпуска, подписи версии и размера, ответ FAQ о поддерживаемых версиях, а также `softwareVersion` и `downloadUrl` в JSON-LD.
3. При изменении интерфейса обновить реальные скриншоты и их подписи. Не публиковать авторизацию, личные билды или ответы API.
4. Обновить дату `lastmod` в `sitemap.xml`.
5. Проверить навигацию, галерею, закрытие диалога, FAQ, мобильную ширину, скачивание и внешние ссылки. После push проверить завершение Pages и публичную страницу.

Название страницы, описание, канонический URL, Open Graph и JSON-LD помогают поисковикам понять страницу. Владение ресурсом Search Console подтверждено владельцем; 19 ноября 2026 года в аккаунте непосредственно подтверждена индексация главной. Это не гарантирует её позицию по конкретному запросу. Живая проверка Google успешно получает Sitemap, но успешная обработка карты в отдельном отчёте на эту дату не подтверждена. Проектный `robots.txt` не добавлен: у GitHub Pages этого вида правила robots читаются из корня домена, а сайт размещён в подпапке.

Сайт не содержит упоминаний инструмента разработки, форм авторизации и донатов. Форумный пост и обращение к разработчикам PoB при публикации сайта не меняются.

## Google Analytics 4 — подключение 19 ноября 2026 года

По поручению владельца создан веб-поток «PoB 2 RU — GitHub Pages» в ресурсе «PoB 2 на русском — сайт». Measurement ID: `G-RJD35VBT5C`, числовой ID потока: `16373986162`. Это публичные идентификаторы, не секреты API. Часовой пояс отчётов — Москва; валюта USD оставлена по умолчанию, продажи не настраиваются.

Код асинхронно загружает стандартный тег Google, регистрирует просмотры и отдельное событие `download_click`. Параметр `button_position` различает `hero` и `footer`, `file_name` содержит имя ZIP. При новом выпуске событие автоматически использует имя из действующего href. Рекламные сигналы отключены в конфигурации тега. Ссылки скачивания и обычное поведение браузера сохраняются, в том числе при блокировке Google. Повторная загрузка скрипта не инициализирует счётчик второй раз.

`download_click` означает нажатие, а не завершённое скачивание и не запуск программы. Включённая в потоке улучшенная статистика может также отправлять `file_download` и `click`; их нельзя складывать с `download_click` как независимые загрузки. Уникальные пользователи и сеансы не равны числу физических людей. Блокировщики ограничивают полноту данных. Посещения до подключения не восстанавливаются, прямые ZIP-ссылки из внешних постов обходят сайт.

Для просмотра без отправки данных использовать `?analytics=off`. Этот параметр действует на текущую загрузку страницы. Скрипт также отключается на локальном файле, другом домене и вне пути проекта. `?analytics_debug=1` включает диагностический режим для DebugView; диагностические визиты учитывать отдельно от аудитории. Не публиковать тестовые ID и секреты Measurement Protocol.

Для будущих публикаций подготовлены ссылки с метками: `utm_source=poe_forum&utm_medium=community&utm_campaign=ru_beta2&utm_content=announcement` для анонса, тот же источник с `utm_content=build_guide` для руководства, `utm_source=steam&utm_medium=guide&utm_campaign=ru_beta2` для Steam и `utm_source=telegram&utm_medium=community&utm_campaign=ru_beta2` для Telegram. Метки добавляются к главному URL. Текущие внешние публикации этим изменением не редактируются.

Перед выпуском аналитики локальные проверки проходят с перехватом запросов к Google и ZIP; настоящие загрузки и фиктивные визиты не создаются. Подключение не считать подтверждённым только по наличию кода: проверить публикацию и реальное поступление событий в GA4. Фактический результат живой проверки записывается в карточке проекта владельца.

Сбор статистики производится только через Google Analytics. По прямому требованию владельца сервисы Яндекса не используются.
