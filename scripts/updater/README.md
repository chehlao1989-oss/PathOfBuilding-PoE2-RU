# Обновление переносимой русской PoB

С beta 3 кнопка «Обновления» находится рядом с «Поддержать проект». При запуске и каждые 12 часов PoB получает список последних 30 опубликованных выпусков из GitHub API репозитория chehlao1989-oss/PathOfBuilding-PoE2-RU. Проверить вручную можно кнопкой или Ctrl+U. При ошибке сети ручная проверка показывает сообщение.

Для нового выпуска увеличьте версию в localization/release.json. Поддерживаются теги vX.Y.Z-ru.N-beta.B и vX.Y.Z-ru.N. При равных X.Y.Z и N стабильная сборка старше любой беты. В выпуск загрузите PoB2-RU-VERSION-Windows.zip под точным именем из archiveName. Для проверки установщик использует SHA-256 этого файла из метаданных GitHub. Сборкам beta 1 и beta 2 требуется один ручной переход.

После согласия игрока обновляющий процесс скачивает ZIP, проверяет хеш, распаковывает его во временную папку рядом с прежней сборкой и сверяет версию. Игрок сохраняет изменения и закрывает старое окно PoB. Установщик дожидается выхода процесса, копирует Builds, Settings.xml и imgui.ini и открывает новую версию из отдельной папки. При существующей целевой папке установка останавливается. Произвольные дополнительные файлы остаются в старой папке. Пользовательские пути к билдам сохраняются в Settings.xml. При использовании ярлыка игроку нужно указать новую папку.

Во время загрузки установщик показывает скачанный объём. Если HTTP-ответ содержит положительный Content-Length, показаны также общий объём и процент; иначе указано, что общий размер неизвестен, без фиктивного процента. Обычная консоль обновляет одну строку с возвратом каретки, перенаправленный вывод получает не более одного периодического сообщения в секунду плюс начальные/финальное состояния. Неполный ответ с известным размером отклоняется; при неизвестном размере целостность по-прежнему подтверждается SHA-256.

После 100% остаются отдельные этапы проверки SHA-256, распаковки/метаданных, ожидания закрытия PoB, переноса и запуска. «Готово» печатается после успешного переноса, Process.Start и удаления staging. При ошибке старые файлы сохраняются, указывается причина и повтор через «Обновления» / Ctrl+U. Повтор начинает новый staging и полную загрузку; возобновления непроверенного partial-файла нет. Только ошибка запуска после успешного Install этой попытки предлагает вручную открыть её установленный EXE. Произвольная существующая целевая папка таким советом не помечается.

Исходник установщика находится рядом с этим файлом. Для сборки в Windows из корня репозитория используйте PowerShell с установленным .NET Framework 4.7.2 или новее.

```powershell
& "$env:WINDIR\Microsoft.NET\Framework64\v4.0.30319\csc.exe" /nologo /optimize+ /codepage:65001 /r:System.IO.Compression.dll /r:System.IO.Compression.FileSystem.dll /r:System.Web.Extensions.dll /out:runtime\PoB2RUUpdater.exe scripts\updater\PoB2RUUpdater.cs
```

Рядом с EXE в архиве должен находиться PoB2RUUpdater.exe.config для длинных путей. После пересборки включите проверенный хеш бинарного файла в localization/portable-files.json. scripts/build_ru_release.py проверяет хеши и содержимое ZIP. Проверка выбора выпуска находится в tests/localization/check_ru_updates.lua. RuUpdaterInstallTest.cs компилируется вместе с исходником установщика с ключом /main:RuUpdaterInstallTest. Скопируйте конфигурацию рядом с тестовым EXE под именем этого EXE с суффиксом .config, затем передайте ему путь к локальному ZIP, SHA-256 и тег.

Медленная загрузка, Content-Length/chunked, TCP-обрывы, неполный EOF и повтор поверх partial проверяются без сторонних библиотек:

```powershell
python tests/localization/test_updater_download.py --output <новая-папка-доказательств>
```

Скрипт компилирует отдельный RuUpdaterDownloadTest.Main вместе с production-исходником и запускает loopback HTTP fixture. Он вызывает тот же DownloadFile, но локальный URL задаёт только test Main; в штатном EXE URL по-прежнему фиксирован, CLI остаётся `tag sha256 pid`. TLS/certificate bypass и настройки публичных endpoints не используются. Флаг `--serve` держит эту отдельную фикстуру до stop.txt для внешней проверки консоли/PTY. Тестовые driver/hook файлы не включать в переносимый архив.
